# 复制通用版非注释和空白行

在编辑器中右键选择 **“复制通用版非注释和空白行到剪贴板”**，即可获得去除注释和空白行的代码。也可按 `Ctrl+Shift+P`（macOS：`Cmd+Shift+P`）搜索这个命令。

**有选区就复制选区，没有选区就复制整个当前文档。只写剪贴板，绝不修改编辑器里的原文，也不会自动保存文件。**

## 安装

需要 VS Code **1.99.0 或更高版本**，支持 Windows、macOS 和 Linux 桌面版。

1. 下载 `copy-clean-code-1.0.1.vsix`。
2. 打开 VS Code 的扩展视图，点击右上角 `…`。
3. 选择 **“从 VSIX 安装…” / “Install from VSIX…”**，选中该文件。
4. 打开代码文件，确认右下角的语言模式正确，再运行上述命令。

也可在终端执行：

```sh
code --install-extension copy-clean-code-1.0.1.vsix
```

本扩展未发布到扩展商店，不需要账号。运行时所需语法和分词引擎都在安装包中，不下载语法，不上传代码，不包含遥测。适用于本地、未信任工作区和虚拟文档；不是浏览器版 Web Extension。

## 清理规则

- 删除受支持语法中的整行注释、行尾注释和块注释。
- 保留字符串中的 `//`、`#`、`/* */`、`<!-- -->` 等普通内容，按各语言语法分词，而不是用一个正则表达式全局替换。
- 删除所有空行、只含空格或制表符的行，包括开头、结尾和删除注释后产生的空行。
- 保留剩余代码行的缩进；移除行尾空白，统一用单个 LF（`\n`）分隔，不额外添加末尾换行。
- 行内块注释的删除会保留必要的空格，避免把 `a/* 注释 */b` 错误拼接成 `ab`。可能留有原来注释两侧的多个空格：这不是代码压缩器。
- 全部内容都是注释或空白时，将空字符串写入剪贴板。
- 多光标场景使用**主选区**，不拼接多个离散选区。选区开始于多行注释或字符串中间时，会使用此前的文档内容恢复分词上下文。
- 未支持的语言会明确提示，**保留原剪贴板不变**。不会将纯文本强行按某个编程语言处理。

## 支持的语言

语言由 **VS Code 当前文档的语言模式 ID** 决定，不只看文件后缀；例如带注释的 JSON 推荐使用“JSON with Comments”。

| 语言模式 | 主要识别的注释形式 |
| --- | --- |
| JavaScript / TypeScript / JSX / TSX | `//`、`/* ... */`，区分字符串、模板字符串和常见正则字面量 |
| JSON / JSONC | JSONC 中的 `//`、`/* ... */`；普通 JSON 按对应 JSON 语法处理 |
| C / C++ / C# / Java | `//`、`/* ... */`，字符串按各自语法处理 |
| Python | `#`；三引号字符串和 docstring 是字符串，**不会作为注释删除** |
| Shell Script（Bash 语法） | `#`，区分引号字符串、常见参数展开和 here-document |
| YAML | `#`，区分引号字符串与块标量 |
| TOML | `#`，区分普通字符串和多行字符串 |
| SQL | 通用 SQL 语法中的 `--`、`/* ... */`；不承诺所有数据库方言 |
| HTML / XML | `<!-- ... -->`；HTML 的内嵌脚本/样式由所加载的语法处理 |
| CSS | `/* ... */`；`//` 不是标准 CSS 注释 |
| SCSS / Less | 块注释及该语法支持的 `//` 注释 |
| PowerShell | `#`、`<# ... #>`，区分引号字符串和 here-string |
| Rust / Go | `//`、`/* ... */`，按语言语法区分字符串 |
| Nginx | `#`（仅在引号外；支持整行和行尾注释） |

Nginx 语言模式的显示名是 **Nginx**，会自动匹配文件名 `nginx.conf` 和后缀 `.nginx`；普通 `.conf` 文件不会被扩展自动指定为 Nginx，需在右下角手动选择该模式。第三方语法扩展提供的语言模式 ID `nginx-conf` 和 `nginxconf` 也会按 Nginx 规则处理，但扩展不会重复注册这些 ID。Nginx 的单引号、双引号内容会保留其中的 `#`，并处理转义引号、反斜杠和 `\#`；按原生 token 边界，参数内部的 `foo#bar` 也保留，只有 token 起始或分隔符后的 `#` 才开始注释。`//`、`/* ... */` 不是 Nginx 注释。此模式使用专用逐字符词法状态机，不是语义编译器；OpenResty 中嵌入的 Lua/Perl 不按原生 Nginx 注释承诺处理。其他清理规则保持不变。

## 使用前需要知道

这是**多语言语法分词清理器，不是编译器，也不是语义保真格式化工具**。底层采用 [Shiki](https://shiki.style/) / TextMate 与 Oniguruma，按语法作用域判断真正的注释；[Shiki 官方也使用相同的注释元数据实现删除注释](https://shiki.style/packages/transformers#transformerremovecomments)。

1. **空白行会无条件移除，包括多行字符串、YAML 块标量、Shell heredoc 等内容里的空白行。** 这是本命令“不要空白行”的明确规则，但可能改变这些字面量的实际值。代码行本身仍保持分行；不会把所有代码压成一行。
2. 注释里的许可证、类型检查指令、格式化控制指令、SQL 优化器提示、Shell shebang 等也可能被删掉。清理结果主要供复制使用，不保证可直接替代原文件执行。
3. 不支持的语言（例如 Markdown、纯文本、自定义 DSL）、第三方自定义语法扩展、所有数据库方言、所有语言最新特性及特殊预处理器都不作覆盖保证。畸形/未闭合的字符串或注释，或从语法单位中间截取的选区，可能有语法分词器自身的局限。
4. Python 的三引号“注释”实际上是字符串表达式，保留是有意设计；Shell 的 `: '...'` 也不是 `#` 注释，不会作为注释删掉。
5. 只针对主选区或当前文档；不批量扫描项目，不改磁盘文件，不修改系统剪贴板以外的内容。处理很长的文档或极长单行时可能需要等待。
6. 语法识别来自扩展内固定版本的语法库，不自动跟随 VS Code 或其他语法扩展更新。遇到边界语法请先对照原文检查剪贴板结果。

## 源码构建与测试

构建环境需要 Node.js 20 或更高版本、npm；运行实际 VS Code 集成测试还需 Linux 的 Xvfb/桌面环境或对应系统的桌面环境。

```sh
npm ci
npm run build
npm test
npm run package
npm run test:integration
```

`npm run package` 使用官方 `@vscode/vsce` 生成 `artifacts/copy-clean-code-1.0.1.vsix`，将运行时依赖打入 `dist/extension.cjs`，无需安装时再执行 npm。`test:integration` 脚本默认用 Linux 的 `xvfb-run`；其他系统可直接运行 `node test/run-integration.cjs`。

单元测试覆盖多语言注释、字符串保护、行内块注释、选区前文上下文和空白行；集成测试会把真实 VSIX 安装到工程内的独立测试目录，并验证激活、命令、剪贴板和原文不变，**不会安装到用户的日常 VS Code 环境**。
